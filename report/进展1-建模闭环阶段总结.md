# 进展 1：数据处理、特征工程与第一版建模闭环总结

## 1. 当前阶段目标

本阶段围绕 KDD Cup 2017 高速公路收费站交通流量预测任务，完成从原始数据到第一版可提交预测结果的基础闭环。

核心目标包括：

- 将逐车通行记录处理为 20 分钟粒度车流量。
- 构造符合题目限制的滑动窗口监督学习样本。
- 融合时间、天气、路线与拓扑特征。
- 使用时间顺序切分训练集和验证集，避免数据泄露。
- 训练 baseline 模型和 XGBoost 主模型。
- 生成第一版 `submission_phase1.csv`。

## 2. 已完成工作

### 2.1 Volume 数据处理

已实现脚本：

```text
src/data_cleaning.py
```

处理逻辑：

- 读取训练集和测试 phase1 的逐车 volume 原始数据。
- 按 `tollgate_id + direction + 20分钟窗口` 聚合车流量。
- 补齐无车辆记录的窗口，缺失流量填为 `0`。
- 仅保留题目要求的 5 个收费站方向组合：
  - `(1, 0)`
  - `(1, 1)`
  - `(2, 0)`
  - `(3, 0)`
  - `(3, 1)`
- 对训练集用 IQR 方法标记异常流量。
- 使用只基于过去窗口的滚动中位数生成 `volume_smooth`，避免未来信息泄露。
- 对测试期仅保留题目允许使用的先验窗口：
  - `06:00-08:00`
  - `15:00-17:00`
- 生成预测期高峰时段提交模板。

输出文件：

```text
data/processed/volume_train_20min.csv
data/processed/volume_test_known_20min.csv
data/processed/volume_observed_20min.csv
data/submission/submission_template_phase1.csv
```

关键检查结果：

- 训练集行数：`10440`
- 测试先验窗口行数：`420`
- 预测模板行数：`420`
- 无重复窗口键。
- 无负流量。
- 测试先验数据没有混入目标高峰窗口。

### 2.2 滑动窗口特征工程

已实现脚本：

```text
src/feature_engineering.py
```

构造方式：

- 使用高峰前 2 小时的 6 个 20 分钟窗口作为历史流量输入。
- 上午预测：
  - 使用 `06:00-08:00` 的 6 个窗口。
  - 预测 `08:00-10:00` 的 6 个窗口。
- 下午预测：
  - 使用 `15:00-17:00` 的 6 个窗口。
  - 预测 `17:00-19:00` 的 6 个窗口。
- 每个目标窗口加入 `horizon_step`，表示预测的是未来第几个 20 分钟窗口。

已构造的流量特征包括：

```text
lag_1_volume ~ lag_6_volume
lead_2h_sum
lead_2h_mean
lead_2h_max
lead_2h_min
lead_2h_std
lead_1h_sum
lead_1h_mean
lead_trend
```

已融合的时间特征包括：

```text
hour
minute
window_index
weekday
is_weekend
is_morning_peak
is_evening_peak
horizon_step
session_id
```

已融合的天气特征包括：

```text
pressure
sea_pressure
wind_direction
wind_speed
temperature
rel_humidity
precipitation
weather_observation_lag_hours
```

天气匹配原则：

- 对目标窗口匹配不晚于目标时间的最近一次天气观测。
- 例如目标窗口为 `08:00`，可使用 `06:00` 天气，不使用 `09:00` 天气。

已融合的路线与拓扑特征包括：

```text
route_mean_lane_width_mean
```

输出文件：

```text

data/processed/predict_features_phase1.csv
data/processed/route_topology_features.csv
```

### 2.3 第一版模型训练与预测

已实现脚本：

```text
src/train_model.py
src/utils.py
```

训练策略：

- 按时间顺序切分训练集和验证集。
- 训练集：`2016-09-19` 至 `2016-10-10`
- 验证集：`2016-10-11` 至 `2016-10-17`
- 不使用随机切分，避免时间序列数据泄露。

已实现模型：

- Ridge 回归：作为线性 baseline。
- XGBoost 回归：作为当前主模型。

评价指标：

```text
MAPE = average(|真实值 - 预测值| / 真实值)
```

对真实值为 `0` 的样本进行了保护，避免除零。

当前验证结果：

| 模型 | 验证集 MAPE |
| --- | ---: |
| Ridge | 0.407277 |
| XGBoost | 0.172920 |

XGBoost 明显优于 Ridge，说明当前滑动窗口特征、时间特征、天气特征和拓扑特征对预测有明显帮助。

按收费站方向组合的 XGBoost 验证 MAPE：

| 组合 | XGBoost MAPE |
| --- | ---: |
| `1_0` | 0.297464 |
| `1_1` | 0.173067 |
| `2_0` | 0.147628 |
| `3_0` | 0.121755 |
| `3_1` | 0.124687 |

按早晚高峰的 XGBoost 验证 MAPE：

| 时段 | XGBoost MAPE |
| --- | ---: |
| morning | 0.162821 |
| evening | 0.183019 |

输出文件：

```text
data/processed/validation_predictions.csv
data/processed/model_metrics.csv
data/submission/submission_phase1.csv
```

提交文件检查结果：

- 行数：`420`
- 字段：`tollgate_id,time_window,direction,volume`
- `volume` 无缺失值。
- `volume` 无负值。
- 提交窗口与模板完全一致。

## 3. 当前成果评价

目前项目已经完成第一版完整建模闭环，具备以下优点：

- 数据处理流程清晰，能从原始逐车记录稳定生成 20 分钟流量表。
- 特征工程符合题目设定，使用预测窗口之前的 2 小时先验流量。
- 天气特征使用不晚于目标时间的观测，避免未来信息泄露。
- 路线和拓扑特征已作为静态特征融合进模型。
- 模型验证采用时间顺序切分，符合交通流量预测任务特点。
- 已有 baseline 与 XGBoost 对照，便于课程报告说明模型改进效果。
- 已生成第一版可提交预测文件。

当前主要不足：

- 对 `tollgate_id=1, direction=0` 的预测误差较高，MAPE 接近 `0.30`。
- 晚高峰误差略高于早高峰，说明晚高峰波动性更强。
- 当前只使用统一 XGBoost 模型，没有针对不同收费站方向分别建模。
- 尚未生成可视化图表，报告支撑材料还不够充分。
- 尚未进行系统调参和模型融合。

### 4.2 针对高误差组合优化

当前误差最高的是：

```text
tollgate_id=1, direction=0
```

后续可重点分析：

- 该组合是否存在更多异常值。
- 早晚高峰流量波动是否更剧烈。
- 是否需要对该组合单独训练模型。
- 是否需要引入更强的历史统计特征。

### 4.3 增加历史周期特征

当前主要使用当天高峰前 2 小时先验流量。后续可增加：

- 同一收费站方向、同一日内窗口的历史均值。
- 同一星期几、同一窗口的历史均值。
- 前一天同一高峰窗口的历史流量。
- 最近 3 天同一窗口的均值和中位数。

这些特征可能改善 `horizon_step` 较远窗口的预测效果。

### 4.4 尝试分组建模

当前模型是统一模型，即 5 个收费站方向组合共用一个 XGBoost。

后续可以尝试：

- 为 5 个 `combo_id` 分别训练模型。
- 为早高峰和晚高峰分别训练模型。
- 为不同 `horizon_step` 分别训练模型。

优先级建议：

1. 按 `combo_id` 分模型。
2. 按 `session` 分模型。
3. 按 `horizon_step` 分模型。

### 4.5 模型调参与简单融合

在评估脚本完善后，可进行模型优化：

- 调整 XGBoost 参数：
  - `n_estimators`

融合前必须先在验证集上比较，不能只看训练效果。
