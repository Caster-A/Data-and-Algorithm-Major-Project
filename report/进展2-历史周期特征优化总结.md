# 进展 2：历史周期特征优化总结

## 1. 本阶段目标

在进展 1 中，项目已经完成第一版完整建模闭环：

```text
数据清洗 -> 特征工程 -> 模型训练 -> 验证评估 -> 生成提交文件
```

进展 2 的目标是在不改变整体流程的前提下，基于评估结果进行第一轮有针对性的优化。

进展 1 的主要问题是：

- `combo_id=1_0` 的误差最高。
- `horizon_step=6` 的误差最高。
- 晚高峰误差略高于早高峰。

因此，本阶段重点增强模型对历史周期规律的表达能力。

## 2. 本次优化内容

本次主要修改：

```text
src/feature_engineering.py
```

在原有特征基础上新增历史周期统计特征。

新增特征包括：

```text
hist_combo_mean
hist_combo_median
hist_combo_window_mean
hist_combo_window_median
hist_combo_window_std
hist_combo_weekday_window_mean
hist_combo_weekday_window_median
recent_3day_same_window_mean
recent_7day_same_window_mean
previous_day_same_window_volume
```

这些特征分别表达：

- 某个收费站方向组合的历史整体流量水平。
- 某个收费站方向组合在同一日内时间窗口的历史规律。
- 某个收费站方向组合在同一星期几、同一窗口的周期规律。
- 最近 3 天、最近 7 天同一窗口的短期趋势。
- 前一天同一窗口的流量水平。

## 3. 防止数据泄露的处理

历史特征构造时严格遵守时间顺序。

对每一行样本，只使用：

```text
time_window_start < target_time
```

的历史数据。

也就是说：

- 训练样本不会使用目标窗口之后的数据。
- 测试预测样本只使用训练期历史数据和测试期允许使用的先验窗口。
- 不使用预测高峰期真实流量。

这保证了新增历史统计特征不会引入未来信息。

## 5. 优化前后结果对比

| Ridge | 0.407277 | 0.261726 | -0.145551 |

Ridge 提升明显，说明新增历史周期统计特征本身具有较强解释力。

XGBoost 原本已经能捕捉较多非线性关系，因此本轮提升幅度较小，但整体仍然下降。

## 6. 当前结论

本轮历史周期统计特征优化是有效的。

主要结论：

- 整体 XGBoost MAPE 从 `0.172920` 降至 `0.169450`。
- `combo_id=1_0` 的误差有明显下降，但仍是当前最难预测的组合。
- `horizon_step=6` 仍然是误差最高的预测步长，说明越远的未来窗口越难预测。
- Ridge 的大幅提升说明历史周期特征对交通流量预测具有较强解释力。
- 当前模型已经进入“特征有效，但需要分组建模或模型结构优化”的阶段。

## 7. 后续优化计划

下一步建议从“统一模型”转向“分组模型”。

优先尝试：

```text
按 combo_id 分别训练 XGBoost
```

原因：

- 当前 5 个收费站方向组合的误差差异明显。
- `1_0` 的误差显著高于其他组合。
- 统一模型可能无法充分拟合每个组合各自的流量规律。

建议后续执行顺序：

1. 在 `train_model.py` 中新增按 `combo_id` 分模型训练逻辑。
2. 保留当前统一 XGBoost 作为对照。
3. 在验证集上比较：
   - unified XGBoost
   - per-combo XGBoost
4. 如果 per-combo 模型整体 MAPE 下降，则用于生成新的提交文件。
5. 如果只有部分组合改善，可考虑混合策略：

```text
1_0 使用单独模型
其他组合继续使用统一模型
```

再之后可以尝试：

- 按 `session` 分别训练模型。
- 对 XGBoost 做小范围参数搜索。
- 尝试 ExtraTrees 或 RandomForest 与 XGBoost 简单加权融合。
